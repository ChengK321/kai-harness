# Kai V0.9 Observation Integration Design

Status: Proposed / Design Only

## 1. Goal

V0.9 Observation Integration connects registered environments with existing Observation Contracts. It does not build a monitoring platform, telemetry backend, or automatic diagnosis system.

## 2. Boundary

```text
Environment Registry
        |
        v
Environment Adapter
        |
        v
Observation Provider
        |
        v
Observation Contract
        |
        v
Governance / Agent Consumer
```

## 3. Responsibilities

### Registry
Provides trusted environment identity and capability references.

### Adapter
Converts environment-specific information into Kai Observation format.

### Provider
Requests observations and returns contract-compatible data.

### Observation Contract
Defines portable read-only state representation.

## 4. Non Goals

- No metrics storage platform
- No replacement for OpenTelemetry or Prometheus
- No automatic remediation
- No workflow engine
- No execution permission

## 5. Identity Binding

Observation must reference an environment_id from a trusted registry. An adapter cannot create arbitrary environment identity during collection.

## 6. Future VPS Example

```text
VPS Registry Entry
        |
        v
VPS Observation Adapter
        |
        v
CPU / Memory / Service State
        |
        v
Observation Contract
```

The adapter observes; it does not restart services or modify the environment.
