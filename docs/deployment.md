# Kai V1.0 部署规范

## 部署流程

1. 只读检查主机、目录、端口、依赖和当前版本。
2. 校验待发布制品的来源、校验和、配置语法及兼容性。
3. 创建不可变版本目录，并生成发布清单；敏感配置通过受控运行时注入。
4. 在隔离环境执行配置、启动和最小功能测试。
5. 切换版本指针或流量，保留上一稳定版本。
6. 执行健康检查并观察错误率、延迟和资源用量。
7. 记录操作者、版本、时间、变更摘要和验证结果。

## 版本管理

- 应用、配置、数据模式和接口契约分别版本化，发布清单记录其组合。
- 推荐语义化版本；每个制品包含构建来源、提交标识、校验和及构建时间。
- `/opt/kai/versions/` 保存版本元数据，不在原位修改已发布制品。

## 发布

发布前必须完成配置校验、安全检查、备份验证和回滚演练。优先采用可逐步放量的发布方式；变更窗口内持续记录审计事件。发布成功以健康检查和验收用例通过为准，而非仅以进程启动为准。

## 回滚

触发条件包括健康检查失败、错误率超阈值、关键能力不可用或安全异常。回滚时切回上一已验证版本及其兼容配置；涉及数据模式时使用预先验证的向后兼容方案或恢复点。回滚后再次执行健康检查并保留故障现场与日志。

## 健康检查

- **存活**：进程或运行时能响应，不执行昂贵外部调用。
- **就绪**：必要配置、Memory、工具注册表和关键依赖可用。
- **深度检查**：按需验证端到端链路，不作为高频探针。
- 响应不得包含 secret；探针应有短超时和明确状态码，并输出版本与时间戳等非敏感信息。
