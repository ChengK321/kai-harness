# Kai V1.0-D3.1 Capability Verification Alignment

Status: Design

## Purpose

Define the relationship between Capability Reference, Execution Evidence and Verification Contract.

Capability describes available ability. It does not mean Kai owns execution.

## Model

```
Capability Reference
        |
        v
Existing Tool / Service
        |
        v
Execution Evidence
        |
        v
Verification Contract
        |
        v
Observation Result
```

## Boundary

Kai may associate:
- capability identity
- execution evidence reference
- verification requirement

Kai does not:
- execute commands
- determine recovery strategy
- implement domain validation

## Example

restart_service capability:

Execution evidence:
- request accepted
- operation id
- provider result

Verification:
- service healthy
- endpoint available
- observation timestamp valid

Execution success is not equivalent to business success.
