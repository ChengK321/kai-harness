# Kai V1.1-D2 Capability Binding Design

Status: Proposed / Design Prototype

## Goal

Define how Kai references external capabilities without owning execution.

The purpose of capability binding is to connect Governance with an existing capability provider while preserving the Control Plane boundary.

## Boundary

```
Kai Control Plane
        |
        v
Capability Reference
        |
        v
Capability Provider
        |
        v
Environment
```

Kai stores and validates references. It does not execute commands or manage runtime processes.

## Capability Reference

A capability reference contains:

- capability identity
- provider identity
- supported operation class
- required verification contract
- governance requirements

Example:

```yaml
capability_id: service.status.read
provider_id: vps-status-provider-001
mode: readonly
verification: service-status-contract
```

## First Prototype Capability

V1.1 only targets read-only capabilities:

- service.status.read
- health.check.read

Excluded:

- restart_service
- deploy
- configuration mutation
- shell execution

## Design Rule

Capability existence does not grant execution authority.

A registered capability only states that an external provider can expose a bounded ability. Governance and environment policies remain authoritative.

## Data Flow

```
Observation
    |
    v
Capability Reference
    |
    v
Provider Query
    |
    v
Evidence Result
    |
    v
Verification
```

## Future

Controlled write capabilities require separate review of approval binding, execution evidence and verification semantics.
