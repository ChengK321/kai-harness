# Kai V1.0 安全规范

## Agent 权限边界

Agent 默认无权限，仅获得当前任务所需的最小能力。读取、写入、执行、联网和外部副作用分别授权；高风险操作必须显式审批。不同用户、会话和环境的数据及凭据相互隔离，权限不能通过提示词扩大。

## Tool 白名单

仅允许调用 `tools-policy.yaml` 中启用的工具。策略同时约束参数、路径、域名、超时、输出大小和审批条件；未知工具与未知参数默认拒绝。工具调用必须携带主体、会话、关联 ID 和策略版本并写入审计日志。

## Docker 权限

- 禁止默认使用 privileged 模式、宿主网络或 Docker socket。
- 使用非 root 用户、只读根文件系统、能力最小化和资源限额。
- 仅挂载明确需要的目录，并限定为只读或最小写入范围。
- 镜像固定到可验证版本或 digest，部署前进行来源与漏洞检查。

## Secrets 管理

仓库、文档、日志和静态 YAML 不保存密码、token、私钥或 secret。凭据由外部 secret 管理能力或受控环境变量在运行时注入，按服务和环境隔离并定期轮换。日志、错误信息和工具输出必须脱敏；发现泄露时立即吊销、轮换并审计影响范围。

## Audit 日志

审计范围包括身份验证、策略判定、Memory 访问、工具调用、审批、配置变更、发布和回滚。日志包含时间、主体、动作、目标、结果、关联 ID 和策略/版本标识，但不记录 secret 或不必要的原始内容。日志采用追加写、访问受控、保留期明确的存储，并对篡改和异常访问告警。

## Human Approval Layer

审批链为：

`Agent → Policy Engine → Approval Gateway → Tool Executor → Environment`

- Agent 只能提出动作意图和参数，不能声明自己已经获得审批。
- Policy Engine 根据注册信息、权限、资源、参数、主体和风险决定自动放行、请求审批或拒绝。
- Approval Gateway 向授权人展示动作、影响范围、参数摘要、过期时间和回滚信息，验证审批主体并签发一次性决定。
- Tool Executor 校验审批决定与原请求、策略版本、参数摘要及有效期绑定后才执行；请求变化使旧审批失效。
- Environment 只接受 Tool Executor 的受控请求；审批不能绕过环境自身安全联锁。

| 权限等级 | 审批要求 |
| --- | --- |
| `READONLY` | 已注册、参数合规、范围明确且无敏感越权时可自动执行；Policy Engine 仍可升级审批或拒绝 |
| `CONTROLLED` | 低风险、可逆、幂等且命中显式策略的部分操作可自动执行；涉及外部副作用、不可逆变更、扩大范围或异常上下文时需要审批 |
| `ADMIN` | 每次都必须由具备对应范围权限的人明确确认；禁止 Agent 自批、批量预批或复用历史审批 |

任务等待审批时使用 `status=waiting_human` 和 `wait_reason=requires_approval`。审批必须绑定 `approval_id`、`audit_id`、请求摘要哈希、审批主体、动作与资源范围、策略版本、签发时间和过期时间；只能使用一次，拒绝或过期后 fail closed。

审批事件：

- `approval.requested`：Policy Engine 判定需人工确认后产生，包含审批 ID、风险摘要、动作与资源范围、所需角色和过期时间。
- `approval.granted`：Approval Gateway 验证授权人并批准后产生，包含审批主体、约束、策略版本和决定时间，不包含凭据。
- `approval.denied`：审批人拒绝、请求过期或请求发生变化时产生，包含非敏感原因和决定来源。

所有审批事件采用 `event-schema.md` 的统一信封并关联任务状态事件。事件不能替代 Tool Executor 对审批有效性和完整性的再次校验。
