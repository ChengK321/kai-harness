# Kai V1.1-D1 Readonly Capability Provider Design

Status: Proposed / Prototype Design

## 1. Goal

V1.1 does not introduce an Executor. The first capability provider validates the boundary between Kai Governance and external environment capabilities.

Target flow:

```
Environment
    |
    v
Capability Provider
    |
    v
Observation Contract
    |
    v
Kai Verification
```

## 2. Scope

Included:

- service.status.read
- health.check.read
- evidence generation

Excluded:

- restart_service
- shell execution
- SSH management
- deployment workflow
- automatic recovery

## 3. Responsibility Boundary

Kai:

- validates capability reference
- associates environment identity
- consumes evidence
- evaluates verification contract

Provider:

- queries environment state
- converts raw result into capability evidence
- does not make decisions

Environment:

- remains source of truth

## 4. Minimal Contract

Example:

```yaml
capability:
  id: service.status.read
  mode: readonly

provider:
  id: service-status-provider

output:
  evidence:
    service_name: nginx
    state: active
    timestamp: generated_at
```

## 5. Design Constraints

The provider must not become:

- Agent runtime
- Workflow engine
- Policy engine
- Generic executor

The first prototype only proves safe observation integration.
