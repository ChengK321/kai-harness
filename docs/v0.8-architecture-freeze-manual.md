# Kai V0.8 Architecture Freeze Manual

> Kai Governance Control Plane Baseline
>
> Version: V0.8.0

## 1. Why V0.8 Exists

Kai evolved from infrastructure exploration into a thin AI Control Plane.

The key question changed:

```
Old question:
How do we build a complete AI agent system?

        ↓

New question:
How do we let external AI systems interact with environments safely?
```

Kai does not replace Agent frameworks, MCP, ROS2, or robot controllers.

It provides boundaries between intelligence and the real world.

## 4. Component Responsibilities

| Component | Responsibility | Does not do |
|---|---|---|
| Harness | Start external Agent | Reasoning loop |
| Observation | Provide state | Diagnosis or repair |
| Intent | Describe requested change | Execute command |
| Validator | Check contract | Approve operation |
| MCP/Tool | Provide capability | Become governed by Kai automatically |
| Environment | Perform operation | Controlled by Kai |

---

## 5. Critical Boundary

Validation success means:

```
The request format satisfies Kai rules
```

It does NOT mean:

```
Approved
    |
Allowed
    |
Executed
    |
Succeeded
```

These facts belong to different systems.

---

## 6. Explicit Non Goals

Kai will not become:

- Agent Runtime
- Workflow Engine
- General Executor
- Robot Controller
- ROS2 replacement
- Memory database
- Tool marketplace

The reason is simple:

```
More capability
        |
        v
More responsibility
        |
        v
More safety risk
```
