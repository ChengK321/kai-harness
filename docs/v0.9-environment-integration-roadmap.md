# Kai V0.9 Environment Integration Roadmap

> From Governance Boundary to Real Environment Validation
>
> Version: V0.9 Design Proposal

---

# 1. Why V0.9 Exists

V0.8 solved one fundamental question:

```
Can AI requests be constrained safely?
```

The answer is:

```
Yes.

Through:

Intent Contract
        |
        v
Validation Boundary
        |
        v
Governance Evidence
```

V0.9 moves to the next question:

```
Can Kai connect real environments
without becoming the system controller?
```

Therefore V0.9 is an integration validation phase, not an execution expansion phase.

# 4. V0.9-B MCP Integration

## MCP 的角色

MCP 是能力连接方式。

不是：

- Agent Runtime
- Workflow Engine
- Security Boundary

架构关系：

```
传统方式：

Agent
 |
 v
MCP
 |
 v
Tool
 |
 v
Environment


Kai方式：

Agent
 |
 v
Kai Governance
 |
 v
MCP Tool
 |
 v
Environment
```

Kai 增加：

- 环境身份
- 请求约束
- 审计关联
- 验证证据

不增加：

- 新 Tool Protocol
- MCP 替代层

# 7. Anti Over Engineering Rules

任何新增能力必须回答三个问题：

## Question 1

已有生态是否已经解决？

例如：

- Agent Loop → Agent SDK
- Tool Protocol → MCP
- Robot Control → ROS2

如果已经存在，不重复建设。

---

## Question 2

Kai 是否增加真实价值？

允许：

```
Identity
Permission Boundary
Evidence
Governance
```

不允许：

```
Executor
Planner
Workflow
Controller
```

---

## Question 3

是否让 Kai 更接近环境控制者？

如果答案是：

```
Yes
```

需要重新审核。
