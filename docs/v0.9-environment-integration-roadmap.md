# Kai V0.9 Environment Integration Roadmap

## Goal

V0.9 is not an execution expansion. It is an integration validation phase.

The goal is to connect Kai governance concepts with real environments while preserving boundaries.

```
Observation
    |
    v
Agent Proposal
    |
    v
Governance Validation
    |
    v
Existing Trusted Capability
    |
    v
Environment
    |
    v
Observation Verification
```

## Phase 1: Capability Inventory

Before integration:

- identify existing tools
- identify MCP services
- identify environment owners
- identify existing approval mechanisms

No new executor is created.

## Phase 2: Read-only Integration

Priority:

- VPS status
- service health observation
- environment metadata

Success criteria:

Kai can understand an environment without controlling it.

## Phase 3: Governed Action Reference

Validate one controlled scenario:

Example:

```
User request
    |
Observation
    |
External Agent suggestion
    |
Governance Intent
    |
Existing approved tool
    |
Verification
```

Kai records governance relationships but does not execute operations.

## Phase 4: Robotics Extension Study

Possible targets:

- ROS2 observation mapping
- robot state verification
- safety evidence reference

Not included:

- trajectory planning
- collision control
- real-time control loop

## Anti-overengineering Rules

Never introduce:

- universal executor
- workflow engine
- autonomous repair loop
- second MCP protocol
- replacement of ROS2

## V0.9 Success Definition

A successful V0.9 demonstrates that Kai can safely connect governance concepts to real environments without becoming the environment controller.
