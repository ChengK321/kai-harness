# Kai V1.1-D5 Provider Integration Review

Status: Design Review / Boundary Check

## Purpose

Review whether Kai should introduce a new Capability Provider implementation or reuse existing Observation components.

## Decision

Do not create a parallel data collection framework.

Existing components such as VPS Observer and Observation Contract remain the source of environment facts. A Capability Provider is introduced only as an integration boundary when an external capability must expose evidence in a controlled form.

## Boundary

```
Environment
    |
    v
Existing Observer / Provider
    |
    v
Observation Evidence
    |
    v
Kai Governance + Verification
```

## Anti-duplication Review

Rejected:

- new generic monitoring platform
- second observation pipeline
- duplicate service discovery
- command execution wrapper
- SSH based executor

Accepted:

- capability reference metadata
- provider identity
- evidence association
- verification binding

## First Prototype Scope

Readonly capability only:

- service status query
- health check query
- evidence generation

No write operation is introduced.

## Next Step

Proceed to minimal adapter implementation only if existing observation modules cannot satisfy the capability contract.
