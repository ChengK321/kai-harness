# Kai V0.9 Observation Integration Design

**Observation = 只读证据。** 观察反映采集到的状态，不决定下一步动作。

```text
受信 Environment Registry 身份 / Provider 引用
                 |
Environment → Adapter → Observation Provider → Observation Contract
                                                  |
                                           Evidence Reference
                                                  |
                                      Governance / Agent Consumer
```

该图为集成目标，非当前已全部接通的数据路径。现有 VPSObserverProvider 实际调用
VPSObserver.collect(environment_id).to_observation()，不缓存、不执行工具。
当前 environment_id 是输入标签；Provider 不读取 Registry，也未核验可信环境绑定。

## Provider 与证据引用

沿用现有设计，Provider metadata 可描述 provider_id、provider_type、contract_version、
supported_environment_types 和只读能力；不携带凭据、命令、部署或调度信息。
Evidence Reference 可关联 evidence_id、environment_id、provider_id、
observation_timestamp、contract_version、freshness_requirement。
这些是设计元数据，不是已经实现的注册服务或证据存储。

不向现有 Observation 1.0 顶层注入 evidence_id；关联应在消费侧明确管理。
原始主机诊断字段继续保留在 Raw Model，跨环境输出遵循现有 Contract。
服务状态、机器人姿态等没有实际采集能力时，不生成虚假证据。

## 消费边界

- 缺失、过期、冲突、身份不匹配和来源不可信必须显式保留，不能静默变成健康。
- 多 Provider 需保留来源和时间，不静默拼成一个“权威事实”；不新增调度或融合引擎。
- 工具成功与目标达成不同；只有对应环境、范围和新鲜度的证据才可支持验证结论。
- 观察异常不触发审批、重试、修复或动作生成。

复用 MCP Resource / 外部遥测来源属于未来适配选择，不建设 Telemetry Platform。
证据参考设计不意味着授权环境读取，更不授予环境修改权限。
