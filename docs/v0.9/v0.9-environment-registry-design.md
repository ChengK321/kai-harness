# Kai V0.9 Environment Registry Design

## 定位

Environment Registry 是环境身份与声明引用索引，不是 CMDB、凭据仓库、部署系统或授权系统。
注册不等于连接，声明 capability 不等于拥有可调用权限。

```text
Environment Identity
        |
Environment Registry
        |
        +-- Observation Provider Reference
        +-- Capability Reference
        +-- Governance 目标关联
```

## 仓库当前事实

[内存原型](../../apps/environment-registry/environment_registry.py)提供 EnvironmentRecord：
environment_id、environment_type、trust_level、capabilities；支持 register/get/has_capability，
拒绝重复 environment_id。它没有持久化、网络、认证或执行能力。
trust_level 只是声明，has_capability 只是列表查询，不验证运行可用性或授权。
原型也没有完整的字段/引用校验；frozen dataclass 不使内部 capabilities 列表深度不可变。

现有 [Environment Registry 配置](../../configs/registry/environment-registry.yaml)与内存原型
是不同表示，本阶段不自动互转或合并。配置中的 type 与原型 environment_type、
未来 provider/adapter 引用之间的映射需单独确认，不宣称原型已加载 YAML。

## 集成边界

未来集成需由受信入口提供环境身份，显式核验 Provider 和 Capability 引用。
不能用任意 hostname、IP 或 SSH 地址代替 Registry 身份，不在声明中存储凭据或命令。
不自动发现、同步、连接、探测或执行环境。

当前 vps-primary 仍为 registered/declarative_only/connected=false；
execution_enabled=false、require_tool_executor=true 保持不变。
任何未来解释或迁移需独立审核，不通过文档将这些限制视为已满足。
