# V0.9 Observation Multi Provider Boundary Review

Status: Design review

## Purpose

Define how Kai handles multiple Observation Providers without becoming a telemetry aggregation platform.

## Boundary

```
Environment
    |
    +----------------+
    |                |
    v                v
 Provider A      Provider B
    |                |
    +-------+--------+
            |
            v
 Evidence Reference
            |
            v
 Governance Verification
```

## Decisions

- Environment identity comes from Registry, not Provider.
- Providers provide observations, not authority.
- Evidence references identify sources but do not copy telemetry data.
- Conflicting observations remain explicit; Kai does not silently merge facts.
- Freshness and trust requirements are validation inputs, not an alert engine.

## Rejected Expansion

Kai does not provide:

- telemetry storage
- metric aggregation
- alerting
- automatic remediation
- provider marketplace

## Conflict Handling

When providers disagree, the result is unknown/unverified unless an external policy defines how evidence is selected.

The Governance layer must not invent domain truth from incomplete observations.
