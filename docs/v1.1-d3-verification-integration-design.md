# Kai V1.1-D3 Verification Integration Design

Status: Proposed

## Goal

Bind Capability Reference with Verification Contract without making Kai an executor.

## Core Principle

Capability execution result is not equal to environment success.

```
Capability Reference
        |
        v
External Capability Provider
        |
        v
Execution Evidence
        |
        v
Verification Contract
        |
        v
Verified Result
```

## Responsibilities

### Kai

- associate capability reference
- require verification contract
- collect evidence references
- evaluate verification status

### Provider

- perform domain operation
- return execution evidence
- expose domain result

### Environment

- provide actual state

## Example

A service provider reports:

```
restart accepted
```

This does not prove:

```
service healthy
application available
user request satisfied
```

Verification must independently check the expected condition.

## Non Goals

Kai does not implement:

- service restart logic
- command execution
- retry workflow
- recovery planner
- domain health algorithm

## Future

D3 prepares the boundary for a readonly provider prototype.
