# Kai V0.9 Observation Identity Binding Design

## 1. Purpose

Define how Environment Registry and Observation Contract cooperate without introducing a new identity system.

## 2. Architecture

```
+----------------------+
| Environment Registry |
|                      |
| environment_id       |
| type                 |
| capability reference |
+----------+-----------+
           |
           v
+----------------------+
| Observation Provider |
|                      |
| collect state        |
| transform output     |
+----------+-----------+
           |
           v
+----------------------+
| Observation Contract |
|                      |
| environment_id       |
| timestamp            |
| observation data     |
+----------------------+
```

## 3. Identity Rules

Environment identity answers:

"Which environment does this observation describe?"

It does not answer:

- who can access it
- who can modify it
- whether an action is approved

Those remain separate Governance responsibilities.

## 4. Multiple Providers

One environment may expose multiple observation sources:

```
Environment
    |
    +-- VPS Provider
    |
    +-- ROS2 Provider
    |
    +-- Cloud Provider
```

Provider identity describes the source, not ownership of environment identity.

## 5. Anti Expansion Rules

Observation integration must not become:

- metrics storage
- alerting system
- dashboard platform
- automatic remediation engine

Kai consumes evidence; specialized systems own collection infrastructure.

## 6. Future

Later versions may define provider registration metadata, freshness requirements and evidence references after real integration scenarios exist.
