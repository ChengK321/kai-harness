# Kai V0.9-D3.1 Capability Reference Model

Status: Design Only

## 1. Purpose

Capability Reference describes what an environment can provide. It does not execute tools, schedule tasks, or replace MCP.

## Boundary

```
Environment Registry
        |
        v
 Capability Reference
        |
 +------+------+------+
 |             |      |
 v             v      v
MCP Tool   Domain API ROS2 Service
        |
        v
 Environment
```

## 2. Capability Responsibility

Capability metadata may describe:

- capability_id
- capability_type
- environment_binding
- provider_reference
- contract_version
- readonly/reference information

It must not contain:

- shell commands
- execution workflow
- retry policy
- planner logic
- model prompts
- credentials

## 3. Boundary Decisions

Capability Reference is not:

- Tool Marketplace
- Executor
- Workflow Engine
- Plugin Manager
- Permission System

Existing execution systems remain responsible for actual invocation and safety checks.

## 4. Relationship With Governance

```
Observation Evidence
        |
        v
Governance Intent
        |
        v
Capability Reference
        |
        v
Existing Tool / MCP / Adapter
```

Governance verifies that an approved intent references an allowed capability. It does not decide business actions.

## 5. Anti-overengineering Check

Before adding capability fields ask:

1. Is this needed to identify or constrain an existing capability?
2. Does an external protocol already provide it?
3. Does adding it create execution ownership?

If yes, the capability model must not absorb it.
